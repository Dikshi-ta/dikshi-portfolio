Web App · Dashboard Design

AI Writing Assistant & Plagiarism Checker

Dashboard Wireframes Prototyping
The problem

Writers needed one place to draft, get suggestions and check originality — instead of switching between separate tools that broke their writing flow.

My role & process
  • Mapped the writer's journey from blank page to final, checked draft

  • Grammar assistance — surface common writing mistakes
  • Plagiarism checker — submit text and review an originality score
  • Writing dashboard — organise tools and recent activity in one place
  • Responsive layout — adapts across desktop and mobile

Healthcare · UX Strategy

Smart LifeLink — Organ Transplant Management Platform

Healthcare User Flows Information Architecture
The problem

Three very different users — hospitals, doctors and patients — needed to move through one shared system, each with different urgency, literacy and context. Managing that through disconnected systems made the workflow hard to organise and monitor.

My role & process
  • Designed separate end-to-end journeys for each user type, then found where they intersect
  • Simplified multi-step hospital workflows into a linear, status-driven flow
  • Prioritised clarity and trust cues given the sensitivity of the subject matter
Outcome & learnings

Designing for three roles at once taught me to lead with shared status information first, then branch into role-specific actions — keeping the system legible for everyone involved.

How the platform works
01
Register donors
Donor and available organ information is recorded.
02
Add recipients
Recipient requirements and medical context are entered.
03
AI matching
The system analyses donor and recipient compatibility.
04
Coordinate & track
Matches are reviewed, transport is monitored and activity is logged.
Key features
  • Donor management — stores and organises donor records
  • Recipient management — tracks requirements and transplant data
  • AI-based matching — surfaces compatible donor–recipient pairs
  • Transport tracking — monitors organ movement end-to-end
  • Admin dashboard — central control over users and activity
  • Audit & records — traceable history of transactions
Tools & technologies
AI / ML concepts PostgreSQL REST APIs Blockchain / audit concepts Figma Postman Responsive UI
Future improvements
  • Real-time transport monitoring and alerts
  • Stronger role-based access controls
  • Detailed analytics and multilingual accessibility

Android · Safety Technology

AI-Powered Local Wake-Word SOS Activation System

Emergency UX Interaction Design Accessibility
The problem

In an emergency, a person may not be able to unlock a phone, open an app or press a button at all. The interface needed to work when almost nothing about the interaction is visual.

My role & process
  • Mapped the voice-triggered flow from wake word to alert sent, second by second
  • Designed a minimal confirmation screen for the rare moments a glance is possible
  • Prioritised big touch targets, high contrast and one-handed reachability
Outcome & learnings

This project pushed me to design for the absence of screen time — the real interface is a sound and a confirmation, not a set of buttons.

How the system works
01
Set up contacts
User configures who should receive the SOS alert.
02
Monitoring runs
A background service listens for the wake word.
03
Trigger detected
A wake word (“Help”, “Aura”) or shake gesture fires.
04
SOS workflow starts
The configured emergency process begins automatically.
Key features
  • Wake-word activation — hands-free trigger using a configured phrase
  • Shake detection — motion-based trigger from device sensors
  • SOS workflow — the emergency process runs without further input
  • Emergency contacts — manage who receives the alert
  • Evidence & contact screen — organises key information for the user
Tools & technologies
Kotlin Android Studio Android Services Device sensors Wake-word detection Android UI components
Future improvements
  • Improve wake-word recognition accuracy
  • Configurable activation phrases and multilingual support
  • Reduce accidental activation through extensive testing

Web · Front-End Build

React Multi-Page Website with Router DOM

Front-End React Router Responsive
The problem

A multi-page site needed clean client-side navigation and a layout that held up across devices, without the design and the build drifting apart. Traditional sites forced a full browser refresh on every page change.

My role & process
  • Designed the page layouts and navigation structure first
  • Built the site myself in React using React Router DOM for page transitions
  • Tested and adjusted breakpoints directly in the browser, not just in Figma
Outcome & learnings

Owning design and build end-to-end made me stricter about spacing and component reuse — decisions that are easy to skip in a static mockup surface fast in real code.

Route structure
/
Home
Banner, featured products and promotional content.
/products
Products
Available products in an organised grid layout.
/products/:id
Product details
Detailed information about a selected product.
/about · /contact
About & Contact
Supporting pages reached without a page reload.
Key features
  • Multi-page navigation — client-side routing via React Router DOM
  • Product grid & detail views — clear pricing and action elements
  • Reusable components — navbar, footer, product card, hero, buttons
  • Responsive design — tested across desktop, tablet and mobile
Tools & technologies
React React Router DOM HTML5 CSS3 JavaScript VS Code
Future improvements
  • Firebase authentication and shopping cart
  • Search, filtering and wishlist functionality
  • Backend and product database integration
